# 审美规则库（Aesthetic Skill）

> 给 AI 直接读取调用的设计准则。**Markdown 这版是给人看的**，
> 机器读请直接用 `rules.json`（同目录），内容一一对应。
>
> 数据来源：29 个 2026 年 Awwwards / FWA / Codrops 获奖站的实测色值拆解
> （数据集 `opencolin/threejs-dashboard` 的 `lib/sites.ts`），
> 加上本项目自己踩过的坑。**不是凭感觉写的。**

---

## 0. 三句话总纲

1. **底色够黑，高饱和才是宝石；底不够黑，高饱和就是廉价彩虹。**
2. 底色**不是纯黑、也不是灰黑**，是**带色相的极深底**。
3. "绚烂"是可以量化的：`死黑占比低` + `高彩度占比高` + `特效持续发生`。

---

## 1. 配色决策树

```
要选配色？先定底色，再定两个强调色。

┌─ 底色（background）
│   必须是【带色相的极深底】，亮度 L* < 12，且 R/G/B 不完全相等
│   ✅ #06030d  #04020a  #070710  #0a0a1a  #070a14
│   ❌ #000000（纯黑，死板）   ❌ #08080b（灰黑，脏）
│
├─ 强调色 A（主，冷）
│   高饱和青/蓝：#5dd0ff  #42e0ff  #70ead1  #1c8cff  #4aa8ff
│
└─ 强调色 B（辅，暖/对比）
    高饱和粉/金：#ff6ad5  #ff8ad1  #ffd24a  #ffd45e  #ffce4d

约束：
  · 两个强调色必须【高饱和 + 互为对比】（冷 vs 暖），不要两个都冷
  · 金色（#ffd24a 系）是 2026 最高频强调色，需要"高级感"时优先用
  · 中性文字色从底色往上提：#e6e6e6（正文）/ #9aa0a6（次要）/ #6b7280（弱化）
  · 全站强调色不超过 2 个，中性色不超过 3 档
```

### 实测获奖站原色（可直接抄）

| 站点 | 底色 | 强调 A | 强调 B |
|---|---|---|---|
| Nova Frontier | `#06030d` | `#5dd0ff` | `#ff6ad5` |
| Perfume | `#04020a` | `#ff3df6` | `#42e0ff` |
| Google Bloom | `#070710` | `#ff8ad1` | `#84ffc9` |
| NYT Grid | `#0b0b0b` | `#ffd24a` | `#1c8cff` |

### 曾经踩过的错（别再犯）

- ❌ 为"高级感"锁死低饱和单色相 —— 顶级站用的全是**高饱和对比双色**
- ❌ 底色用 `#08080b` 灰黑 —— 应该是带色相的极深底
- ❌ accent 用旧的 `#d8be8c` —— 应改成 `#ffd24a` 系

## 2. 字号阶梯（Type Scale）

基准 16px，比例 1.25（Major Third）。**全站只用这 8 档，不许出现第 9 档。**

| 级别 | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `xs`  | 12px | 1.5  | 400 | 角标、时间戳、辅助说明 |
| `sm`  | 14px | 1.5  | 400 | 次要正文、表单标签 |
| `base`| 16px | 1.6  | 400 | **正文默认** |
| `md`  | 20px | 1.5  | 500 | 小标题、卡片标题 |
| `lg`  | 25px | 1.4  | 600 | 区块标题 |
| `xl`  | 31px | 1.3  | 600 | 页面主标题 |
| `2xl` | 39px | 1.2  | 700 | Hero 标题（桌面） |
| `3xl` | 49px | 1.1  | 700 | Hero 标题（大屏） |

规则：
- 中文正文行高 ≥ 1.6（中文没有 x-height 差异，行距不够会糊）
- 每行字符数控制在 **30–45 个汉字**（≈ 60–90 个英文字符）
- 标题字重 ≥ 600，正文 400；不要给正文上 600+
- 移动端把 `2xl/3xl` 降一档（Hero 在手机上用 `xl`）

## 3. 间距系统（Spacing）

基准 **4px**，只用这张表里的值，别的都是错的：

```
4    8    12   16   24   32   48   64   96
```

| 用途 | 值 |
|---|---|
| 图标与文字的间隙 | 4 / 8 |
| 表单元素内部 padding | 8 / 12 |
| 卡片内部 padding | 16 / 24 |
| 卡片之间的 gap | 16 / 24 |
| 区块之间的间距 | 32 / 48 |
| 页面级大分区 | 64 / 96 |
| 页面左右安全边距（桌面） | 32–64 |
| 页面左右安全边距（手机） | 16–20 |

规则：
- **相邻层级间距比不小于 1.5**（16 → 24 → 32，不要 16 → 20）
- 同一视觉组内部间距 < 组与组之间间距（格式塔邻近原则）
- 垂直节奏用 8 的倍数（4 只在图标级用）

## 4. 动效时长表（Motion）

| 类型 | 时长 | 缓动 | 例子 |
|---|---|---|---|
| 微交互 | 120–150ms | `ease-out` | hover、focus、按下反馈 |
| 常规过渡 | 200–300ms | `cubic-bezier(.4,0,.2,1)` | 展开/收起、菜单滑入 |
| 页面级转场 | 400–500ms | `cubic-bezier(.16,1,.3,1)` | 页面切换、模态进出 |
| 强调动画 | 600–800ms | `cubic-bezier(.34,1.56,.64,1)` | 按钮成功态、数字滚动 |
| 氛围/背景 | 持续循环 | linear | 星空、粒子、呼吸光 |

规则：
- **超过 1s 的动画只能用于氛围背景**，交互反馈绝不能超过 500ms
- 入场用 `ease-out`（先快后慢），出场用 `ease-in`
- 位移距离越大，时长越长（100px → 300ms，1000px → 500ms）
- 必须支持 `prefers-reduced-motion: reduce`（关掉位移，保留淡入淡出）
- **"绚烂"的关键：特效必须持续发生**，只在点击时才放的烟花不算绚烂
  —— 要自动、持续、低频地发生

## 5. 禁忌清单（Hard Bans）

做设计 / 写代码时命中下面任何一条，直接判不合格：

**配色**
1. ❌ 纯黑 `#000000` 当底色
2. ❌ 灰黑 `#08080b` / `#111111`（无彩度）当底色
3. ❌ 低饱和单色相（"安全"但平庸，顶级站没有这么干的）
4. ❌ 超过 2 个高饱和强调色
5. ❌ 白底 + 深色文字却还用高饱和强调色（会廉价）
6. ❌ 强调色和正文色对比度不足 3:1

**排版**
7. ❌ 出现不在字号阶梯里的字号
8. ❌ 中文正文行高 < 1.6
9. ❌ 正文一行超过 45 个汉字
10. ❌ 正文用 600+ 字重

**间距**
11. ❌ 出现不在 4/8/12/16/24/32/48/64/96 里的间距值
12. ❌ 相邻层级间距比 < 1.5

**动效**
13. ❌ 交互反馈 > 500ms
14. ❌ 没有 `prefers-reduced-motion` 兜底
15. ❌ 同时跑 3 个以上大面积动效（会晕）

**工程**
16. ❌ 改了 CSS/JS 却不升静态资源版本号 → 用户永远拿旧缓存
17. ❌ 只在 `readPixels` / `drawImage` 层面验证视觉效果
    → 必须用**真实页面合成截图**评估（WebGL buffer 12% 彩度，屏幕可能只有 2%）

## 6. 验收清单（Checklist）

交付前逐条打勾：

- [ ] 底色是带色相的极深底（不是纯黑/灰黑）
- [ ] 强调色恰好 2 个，且高饱和、互为冷暖对比
- [ ] 所有字号都在 8 档阶梯内
- [ ] 中文正文行高 ≥ 1.6，每行 ≤ 45 汉字
- [ ] 所有间距都来自那 9 个值
- [ ] 交互反馈 ≤ 500ms，有 reduced-motion 兜底
- [ ] 背景特效是**持续自动**发生的
- [ ] 用真实浏览器在 1440×900 和 390×844 各截一次，检查无横向溢出
- [ ] 控制台零 error

---

## 7. 给 AI 的用法

```
做视觉相关的活之前：
  1. 读 aesthetic/rules.json（机器可读版）
  2. 按 color.decision_tree 选底色 + 两个强调色
  3. 按 type_scale / spacing / motion 取值，不许自己编数字
  4. 交付前跑 hard_bans 逐条自检
```
